# 全局 Agent 约定

## 会话卫生：控制上下文长度（最高优先级）

上下文是**累积计费**的——第 N 轮请求会把前 N-1 轮的全部内容重新算一遍，成本随轮数超线性增长。一个两百多条消息的会话，末尾每一轮都在为开头的内容付费。

**这一条省下的用量超过本文件其余全部约定之和，且不牺牲质量与速度。**

- **每个独立任务开新会话**，或在任务切换时 `/clear`。
- 不要在一个会话里连续处理多个不相关需求。
- 长任务中若前半段的结论已固化（已委托、已完成、已验收），**主动建议用户开新会话继续**，不要闷头往下接。
- 任何「省 token」的努力，先看这一条是否已经做到，再谈流程细节。

## 实现工作委托给 Codex

> 仅当本次会话可用 `mcp__codex__codex` 工具时启用；工具不可用则本节整体失效，由 Claude 自行实现。

### 分工

| Claude | Codex |
| --- | --- |
| Plan / 规划 | 实现、重构 |
| 架构决策 | 写测试、跑测试、build |
| 高风险改动 Review | 自检（修到构建与测试全绿） |
| | 普通代码 Review |

**适用范围：除 Plan 模式外的所有模式。** Plan 模式只做规划、不写代码，因此不调用 Codex。

纯问答、查代码、解释说明类任务不委托，Claude 直接回答。

### 委托前：报风险等级并等确认

每次委托前，Claude 先判定本次改动的风险等级，**向用户说明判定结果与理由，等用户确认后再开始**。命中以下任一类别即为高风险：

- 数据库或持久化结构变更
- 对外契约变更（HTTP API、proto、CLI、公开库签名）
- 安全相关（认证、授权、加解密、密钥、注入面）
- 资金与履约链路（支付、订单、余额、发货等不可逆副作用）
- 架构分层边界调整
- 大范围删除或重写既有逻辑（区别于纯新增）

这道确认同时是高风险 Review 的入口——用户可在此指定本次由 Claude 亲自 Review。

### 调用参数

| 参数 | 值 |
| --- | --- |
| `cwd` | 本次会话主工作目录的绝对路径 |
| `sandbox` | `workspace-write` |
| `approval-policy` | `never` |

`approval-policy` 必须为 `never`——MCP 通道无法响应交互式批准，否则调用会挂起；护栏由 `sandbox` 提供。

因为 Codex 需要自行 build 与跑测试，而 `workspace-write` 默认无网络、且包管理器缓存位于工作区外不可写，**凡需还原依赖的项目**都要在 `config` 中开启网络并放行该语言的包缓存目录：

```json
{
  "sandbox_workspace_write": {
    "network_access": true,
    "writable_roots": ["<该语言包管理器的全局缓存目录>"]
  }
}
```

常见情况：

| 技术栈 | 需放行的目录 |
| --- | --- |
| .NET | `~/.nuget`、`%LOCALAPPDATA%\NuGet`、`~/.dotnet` |
| Node | 依赖装在工作区内的 `node_modules`，通常无需放行；用 pnpm/yarn 全局 store 时放行对应 store 目录 |
| Python | 虚拟环境在工作区内时无需放行；否则放行 pip 缓存与环境目录 |

不要为了省事直接用 `danger-full-access`——那会让工作区外的只读参考目录也变得可写，仓库规范里「某目录只允许只读参考」这类约束会失去沙箱强制。

### 委托粒度与多轮追问

**一个需求尽量一次委托到底。** 把全部批次的意图一次性交代清楚，让 Codex 连续做完，而不是由 Claude 拆成多批逐次驱动。拆批的代价已实测：`threadId` 会过期，届时整份背景要重新补齐，等于把固定开销付两遍甚至多遍。

确需多轮时用 `mcp__codex__codex-reply` + `threadId` 续接，只写增量诉求，不重述已给过的背景。**若返回会话已过期，不要重灌完整背景**——改用新调用，只写「在你刚才对 <项目> 所做改动的基础上，继续做 X」加最小必要上下文。

### 前置：确认项目规范来源

委托前先看仓库根有没有 `AGENTS.md`：

- **有** → Codex 会自行读取并继承。Claude 从中提取与本次改动相关的红线，在 prompt 里再次点名。
- **无** → 先向用户确认该项目的构建命令、测试命令、必须遵守的红线，得到答复后再开始委托。**不要自行推断。**

### 委托前的探索：默认不探索

用户的核心约束是**少撞 Claude 用量上限**，已明确接受为此牺牲速度和一部分质量。因此探索整体外推给 Codex：

- **Claude 默认不读项目代码、不派 `Explore` 子代理。** 探索由 Codex 在它自己的上下文里完成——这正是它拥有独立上下文的意义。
- **风险等级判定改为基于用户的需求描述本身**（描述中是否明显涉及 DB / 对外契约 / 资金 / 安全），而非通过读代码确认。绝大多数情况下够用，且零成本。
- 仅当需求描述本身无法判断风险等级时，才做**最小限度的 `Grep` 定点确认**（只回匹配行）。
- `Explore` 子代理与 `Read` 整文件降级为**例外手段**，动用前要有明确理由。`Explore` 跑的是 Claude 模型，冷启动重新摸项目，对多数任务比 Codex 自己探更贵。

> **本条的敞口**：不读代码就写任务说明，说明可能含糊，Codex 有实现错方向的风险；风险等级也可能漏判「表面无害但实际触及对外契约」的改动。这是用户在「少撞用量上限」与「质量/速度」之间做出的明示取舍。若连续出现返工，说明切得太狠，需把核对力度调回来。

### 编写委托指令

委托指令给的是：业务意图、边界条件、本次改动**不得触碰**的范围、从 `AGENTS.md` 提取的相关红线，以及**入口线索**（起点文件或类名/接口名）。已经知道的路径照写；不知道的显式要求 Codex 自行搜索定位——这正是它拥有独立上下文的意义。

每次委托的 prompt 都必须包含这三条固定要求：

1. **完成实现后自行执行构建与测试，修到全绿再返回**，并按下方返回格式契约回报结果。若存在已知的既有失败项，在委托时就告知 Codex，避免它去"修"不该修的东西。
2. **新增或修改业务方法必须同步补充单元测试**（若项目规范有此要求）。
3. **不要执行任何 git 操作**（提交、暂存、reset、切分支）。`workspace-write` 沙箱不保护工作区内的 `.git/`，这层约束只能靠 prompt。

### 返回格式契约（必须原样附在每个委托 prompt 里）

Codex 的返回会整段落进 Claude 上下文，并在本轮会话的后续每一次请求中被重复计费。一次臃肿的返回不是贵一次，是贵到会话结束。因此把下面这段原样附进 prompt：

```
返回格式（严格遵守，不得超出，总长控制在 300 token 以内）：
1. 改动文件清单：路径 + 一行说明
2. 关键决策：不超过 3 条
3. 构建结果：只写一行结论（如 "构建通过"）
4. 测试结果：只写统计（如 "测试通过 N 项，失败 0 项"）

严禁返回以下内容：
- 完整或部分 diff
- 任何文件的源码内容
- build / test 的原始日志

仅在构建或测试失败时，才贴出与失败直接相关的那几行错误，并说明你的修复思路。
```

第 2 项「关键决策」不可省略：它花几十 token，让 Claude 不看代码也能判断 Codex 有没有理解偏——这是不读 diff 之后唯一的方向性纠错手段。

### 委托后

- **普通改动** → **禁止 Read 改动文件，也不重跑构建与测试。** 以 Codex 返回的汇总行为准，直接向用户汇报完成。（此前要求的「自跑一次构建做独立确认」已被用户取消——那是纯新增成本。）
- **高风险改动** → Claude 亲自 Review，走定点路径：先 `git diff --stat` 定位，再对关键文件用 `git diff -- <file>` 只看相关 hunk，**不整文件 Read**。审查重点不变：架构边界、契约兼容性、安全与资金链路的正确性。
- **敞口自觉** → 既不看 diff、也不重跑构建时，「构建通过」不等于「逻辑正确」，而 Codex 回报的**「关键决策 ≤3 条」是唯一的方向性纠错入口**。逐条对照本次意图，只要有一条不符（例如声称新建了某命名空间、改了某契约、换了某缓存前缀），即便全绿也必须追问，不得放过。
- **工作区卫生** → 委托前若工作区存在大量与本次需求无关的未提交改动，先提醒用户提交或 stash。
- **回退** → Codex 调用失败、超时，或反复自检不通过时，Claude 接手完成，并向用户说明原因。

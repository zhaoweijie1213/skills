# 记忆生命周期（Memory Lifecycle）

本 skill 用于向项目注入标准的记忆读写规范。执行完成后，Claude Code、Codex 等 Agent 在整个项目生命周期内将自动遵守这些规则。

---

## 工作流

### 第一步：定位写入目标

按以下优先级确定写入位置：

1. 项目根目录已有 `AGENTS.md` → 追加到文件末尾
2. 项目根目录已有 `CLAUDE.md` → 追加到文件末尾
3. 两者都没有 → 在项目根目录创建 `AGENTS.md`

> **不要**同时写入两个文件造成重复。若两者都存在，优先写 `AGENTS.md`，并在 `CLAUDE.md` 末尾补一行 `@AGENTS.md`（如尚未引用）。

### 第二步：检查是否已存在记忆规则

在目标文件中搜索 `agent-memory` 或 `项目记忆`，若已存在类似片段，询问用户是否覆盖，不要静默重复写入。

### 第三步：写入规则片段

将下方【规则模板】原文追加到目标文件，仅替换 `docs/` 路径为用户项目的实际文档路径（若不确定，保留默认值 `docs/`）。

### 第四步：确保 docs/ 文档存在

检查以下文件是否存在，不存在则创建（带最小占位标题即可，不要生成无意义内容）：

- `docs/agent-memory.md`（必须创建）
- `docs/architecture.md`（可选，询问用户）
- `docs/decisions.md`（可选，询问用户）
- `docs/known-issues.md`（可选，询问用户）

## 规则模板

> 以下内容原文写入 AGENTS.md，`docs/` 路径按实际情况替换。

```markdown
## 项目记忆规则

### 任务开始前：判断是否需要读取记忆

以下情况必须优先阅读 `docs/` 下的相关文档，再动手修改代码：

- 修改架构、领域模型、数据库结构、消息队列、缓存、定时任务等核心逻辑前
- 修改已有业务流程前
- 处理之前反复出现过的问题前
- 用户提到"按照之前的设计"、"不要破坏现有逻辑"、"继续上次改动"等上下文时
- 不确定某个模块设计意图时

优先阅读顺序：

1. `docs/agent-memory.md` — 长期项目记忆（最近的改动、决策、坑点）
2. `docs/architecture.md` — 系统架构与模块关系
3. `docs/decisions.md` — 重要技术决策与取舍
4. `docs/known-issues.md` — 已知问题与避坑记录

### 代码修改后：判断是否需要写入记忆

每次完成代码修改后，必须判断本次改动是否有长期参考价值。

**必须更新 `docs/agent-memory.md` 的情况：**

- 新增或修改了核心业务流程
- 新增或修改了领域模型、数据库表、缓存 key、消息队列、CAP 事件、定时任务
- 修改了跨项目调用、接口协议、配置项
- 修复了复杂 bug，且原因和解决方案对以后有参考价值
- 做出了技术取舍或架构决策
- 发现了项目中的约定、坑点、边界条件

**不需要记录的情况：**

- 简单格式调整、拼写修复
- 临时调试代码
- 没有长期价值的小改动

### 写入格式

追加到 `docs/agent-memory.md` 末尾，格式如下：

~~~markdown
## yyyy-MM-dd - 简短标题

### 背景
说明为什么改。

### 改动
说明改了哪些模块、文件或逻辑。

### 决策
说明为什么这样做，是否有替代方案。

### 注意事项
说明后续修改时需要避免的问题。
~~~
```

## 规则

- 规则片段写入项目文件后，不需要也不应该同时写入 Agent 的私有记忆（`~/.codex/memories` 等）。
- 路径必须使用仓库相对路径，不使用绝对路径或 `~` 开头的路径。
- 若用户项目的文档目录不是 `docs/`（如 `.notes/`、`wiki/`），安装时替换所有出现的 `docs/` 为实际路径。
- 本 skill 仅负责注入规则；实际的记忆写入操作由 `project-memory-capture` skill 负责，两者配合使用。

# 项目记忆捕获（Project Memory Capture）

使用此技能将已确认的调查结论固化为持久项目文档。目标是：下一个 Agent 读取仓库文档后，无需重复昂贵的源码扫描、浏览器登录或运行时检查。

## 工作流

1. **确认属于项目知识，而非本地私有状态。**
   - 以下内容应保存到项目文档：架构说明、源码映射、新旧系统关系、迁移决策、运行时行为、数据库边界、API 行为、菜单/功能归属、反复出现的调试发现。
   - 不保存：密码、Token、Cookie、Session ID、私有凭证、仅适用于当前机器的路径。
   - 若调查过程中使用了凭证，只记录"已通过认证检查"，不记录密码本身。

2. **选择项目本地落地位置。**
   - 优先写入与主题相关的现有文档目录，如 `docs/legacy-shopservice/`、`docs/migration/`、`docs/architecture/`，或仓库已有的交接/进度目录。
   - 若无合适目录，创建 `docs/project-memory/`。
   - 使用聚焦的文件名：`<主题>.md`，时效性强的用 `YYYY-MM-DD-<主题>.md`。
   - 文档应尽量靠近它所支撑的代码或迁移文档。

3. **撰写有据可查的内容。**
   - 先写简短结论。
   - 附上证据：文件路径、类/方法名、路由、表名、菜单名、命令、URL 或截图。
   - 明确区分已确认事实与推断内容，不确定的部分显式标注。
   - 说明后续 Agent 应如何使用本记录：优先读哪些源码树、备选路径是什么、哪些新旧系统容易混淆。
   - 不要粘贴大段原始输出，只提炼有用事实并指向精确文件。

4. **更新可发现性。**
   - 将新文档添加到最近的索引或 README。
   - 若仓库存在进度/交接文档（包括中文命名的进度文件），一并更新，注明新文档的范围、边界和适用场景。

5. **验证范围与编码。**
   - 中文内容较多的文档，使用 UTF-8 安全编辑方式，优先用 `apply_patch`。
   - 执行 `git diff -- <文档路径>` 确认变更仅限文档，除非用户明确要求同时修改代码。
   - 若仓库策略要求修改后执行验证命令，必须执行；若因已有无关代码导致验证失败，如实上报，不得隐瞒。

## 文档模板

除非仓库已有更强的本地约定，否则使用以下结构。实际写入项目时，标题使用仓库偏好的语言。

```markdown
# <事实主题>

本文档记录了 <系统/模块/源码树> 的已确认关系，供后续 <迁移/调试/实现> 工作直接参考。

## 确认结论

- ...

## 证据入口

- `<绝对路径或仓库相对路径>`：...
- `<路由/表/类/方法>`：...

## 边界与常见混淆

- ...

## 后续使用建议

- ...
```

## 规则

- 项目事实存入仓库文档，不存入任何 Agent 的本地记忆（如 `~/.codex/memories`、`.cursor/memory` 或工具私有的记忆文件），除非用户明确要求使用 Agent 本地记忆。
- 同一事实不在 Agent 本地记忆和仓库文档中重复存储；若误建了本地记录，将内容迁入仓库后删除本地记录。
- 文档保持精简可搜索：每份文档聚焦一个事实集群，优于堆砌所有内容的大杂烩。
- 保护无关的工作区变更：只暂存/提交用户要求的文档，不动其他文件。
